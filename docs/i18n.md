# UI languages

User-facing strings are moving out of the components into message files, so the interface can be translated. English is the source language and the fallback.

## How it works

- `messages/en.ts` holds every migrated string under a dotted key, grouped by area (`common`, `empty`, and one group per widget as they are migrated).
- `lib/i18n.ts` has the locale registry (`LOCALES`), the typed `translate(locale, key, vars)` function and `readLocale`. It has no React in it, so server code can import it.
- `lib/useT.ts` is the client side: `const t = useT()` in a component, then `t("common.save")` or `t("common.removeNamed", { name })`. Keys are type checked against the English file, so a typo fails the build.
- The chosen language is the `language` setting, mirrored to localStorage. Changing it updates every mounted component at once.

## Strings

- Placeholders are written in braces, `{name}`, and filled from the second argument.
- Plurals are a pair of keys ending in `_one` and `_other`. Call the base key with a numeric `count` and the locale's plural rule picks the form.
- A key missing from a translation falls back to English, so a partial translation is usable.
- Code must not find elements by their visible or accessible label, since labels change with the language. Use a data attribute (`data-widget-settings`, `data-widget-fullscreen`, `data-header-toggle`, `data-widget-refresh`, `data-face-save`, `data-face-cancel`).

## Adding a language

1. Copy `messages/en.ts` to `messages/<code>.ts` and translate the values. Keep the keys and the `{placeholders}`. Type it as `Translation` from `lib/i18n.ts`; any subset of keys is allowed.
2. Register it in `LOCALES` in `lib/i18n.ts` with its label.
3. The settings drawer shows a Language row under Appearance as soon as there is more than one language.

## Migration status

Migrated: the shared widget chrome (header toggle, settings, full screen, refresh, the settings face's save row and reset prompt, the add row), the stepper, and every widget's empty state.

Not migrated yet: text inside each widget and its settings face, the top bar and settings drawer, the keyboard help sheet, the login and admin pages, the digest page, and server error messages. Migrate a file by moving its strings into a group in `messages/en.ts` and replacing them with `t(...)`.
